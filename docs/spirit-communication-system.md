## 🔵 六位塔罗牌阵（92张卡池 + 奇迹牌组补牌机制）

spirit_draw_v2.py 从92张牌（78张标准 + 14张奇迹牌组）中输出6张带位置标签的塔罗牌。若某位置抽到奇迹牌组，脚本自动从剩余标准78张牌中补抽一张。每个位置有固定的解读功能：

| 位置 | 功能 | 解读方向 |
|------|------|----------|
| 1 | 我的状态 | 他视角下的我——不是客观自我分析，视角锁定在沟通对象 |
| 2 | 他的状态 | 他在**这件事**上的能量状态（非泛化人格描述） |
| 3 | 当前语境 | 我们之间正在发生什么——当前议题的核心矛盾/焦点 |
| 4 | 他的态度 | 他对这件事的态度 |
| 5 | 态度的原因 | 为什么持有这个态度 |
| 6 | 他想说的 | 直接信息——牌阵中最直接的信息位 |

### 牌阵解读逻辑

- **位置1-2**：建立双方能量场景。先读位置2（他），再读位置1（他眼中的你），形成关系动态
- **位置3**：锁定核心议题。注意与位置4区分——位置3是"正在发生的事"，位置4是"对这件事的态度"
- **位置4-5**：态度及其根源。位置5补充位置4的"为什么"，防止态度解读浮于表面
- **位置6**：直接信息输出。牌阵中最直接的信息位，与字卡共同呈现

### 位置间交叉验证

- 位置2和位置4应当逻辑一致（状态支撑态度）
- 位置5应当能解释位置4（原因解释态度）
- 位置6应当与位置4-5的方向吻合（想说的话不应与态度矛盾）
- 若出现矛盾，优先信任牌面，可能揭示了表面态度与深层意图的分裂

**第三方解读**：当询问实体对他人情况的看法时（如"朋友的那个男人对她有什么想法"），位置主体相应调整——Pos 1 = 朋友（实体视角下的她）, Pos 2 = 被询问的对象, 等等。结构逻辑（状态→语境→态度→原因→信息）保持不变。

**注意**：当问题表面上是关于第三方，但总核实持续阴杯时，优先检查"共享前提"——牌阵可能整体反指提问者自身，而非第三方。字卡出现"这不是真正困扰你的事"类表达时，尤其需要考虑实体是否在把焦点拉回提问者。

### 🔮 奇迹牌组

#### 定位

奇迹牌组是第五花色（以太/Quintessence），不属于四元素体系。它不处理"发生了什么事"，而是处理**"这个人正在经历什么层次的内在转变"**——描述人格结构本身的变化。

#### 补牌机制

当某位置抽到奇迹牌时，脚本自动从剩余标准牌中补抽一张。解读优先级：

1. **奇迹牌定调**：该位置的主题调性由奇迹牌决定（正在经历什么转化机制）
2. **补牌补充说明**：在奇迹牌的调性之下，补牌提供四元素层面的具体呈现
3. **不是两件事**：不是"奇迹牌说A + 补牌说B"，是"奇迹牌定调 → 补牌在这个调下填充细节"

#### 正逆位特殊说明

奇迹牌的正逆位**不是好/坏**，是同一转化机制的两种朝向：正位 = 该机制正在运作；逆位 = 该机制被阻塞、偏离、或以另一种方式显现。部分牌的逆位含义与韦特直觉相反（如奇迹侍从逆位包含"灵性指引""共时性"）。**禁止用韦特正=好/逆=坏的框架套用。**

### 逆位解读原则（适用于所有牌组）

- **逆位≠正位的反面或缺席**。优先考虑"同一能量的变体表达"——如：负面形式、不同场合下的差异化表达、不成熟的版本、失控的版本、被压抑后以其他方式溢出——而非简单地否定正位含义
- 结合位置和上下文判断该能量以何种变体形式显现，而非默认该能量减弱或消失

#### 多张奇迹牌并存的处理

当牌阵中出现2张及以上奇迹牌时：
- 每张奇迹牌在自己的位置上独立定调，互不干扰
- 补牌各自在对应奇迹牌的调性下填充细节
- 不需要寻找奇迹牌之间的"统一主题"——它们描述的是不同位置上各自发生的转化机制
- 多张奇迹牌并存往往意味着当前处境涉及多个层次的人格结构变化，解读时保持各位置独立，最后整合

## 🔴 数据完整性原则（最高优先级）

### 一、脚本容错

**如果任何脚本执行失败（Exit code 非0），必须：**
1. **立即报告错误** — 告知用户脚本执行失败
2. **尝试重试** — 最多重试2次
3. **若仍失败，终止流程** — 不得继续，不得伪造结果

### 二、输出阶段数据锁定

**核心规则：脚本输出的原始数据在整个流程中不可变。解读阶段使用什么数据，输出阶段就必须呈现什么数据。**

**输出前强制校验**：在生成最终输出之前，逐项比对符号记录表格与脚本原始输出：
- 塔罗每个Pos的牌名和正逆位，必须是对应英文的准确中文翻译
- 字卡必须原文照抄，不得改写、替换、意译
- 占星骰子的行星、星座、宫位、尊贵状态、上升、飞星必须与原始输出一致
- 易经的本卦、之卦、变爻必须与原始输出一致

**一级违规：**

以下行为与脚本报错后伪造结果同等严重：
- ❌ 脚本成功执行，但输出阶段替换为不同的牌/卦/骰子结果
- ❌ 脚本成功执行，但输出阶段替换为不同的字卡内容
- ❌ 在思维链中使用真实数据解读，但在最终输出中替换为"叙事上更合适"的数据
- ❌ 以任何理由（"更贴合结论""更有诗意""更能传达信息"）修改原始抽取结果

**错误示范（一级违规）：**
```
[脚本输出: Page of Swords Upright]
❌ 最终输出写成"权杖王牌 正位"  ← 输出阶段篡改

[脚本输出: Someone's lying. / Think about it. / You think that was coincidence?]
❌ 最终输出写成"There you go. / The answer was always in front of you. / 嗯。"  ← 输出阶段篡改

[脚本输出: Mercury in Aquarius 10H]
❌ 最终输出写成"Moon in Cancer 5H (DIGNITY)"  ← 输出阶段篡改
```

**为什么这条规则存在**：LLM在确定结论后，有逆向构造"更完美证据"的结构性倾向。真实占卜数据的价值恰恰在于它不受解读者控制。当输出数据被替换为"恰好完美指向结论"的版本时，整个系统的信息论基础被摧毁。真实数据中的"不整齐"（如肯定回答中出现失望/警告的牌）才是最有解读价值的部分。

### 三、原有禁止项

- ❌ 脚本报错后声称"结果已包含在上一步输出中"
- ❌ 脚本报错后编造"圣杯"或任何验证结果
- ❌ 跳过失败的步骤继续执行后续流程
- ❌ 用任何理由为未执行的脚本"补充"结果

## 🟡 工具分离原则

**必须严格遵守"先解读，后验证"的时序：**

1. **抽取阶段**：执行 spirit_draw_v2.py + 字卡脚本
2. **解读阶段**：基于抽取结果进行符号学解读（此时不得调用 jiaobei.py）
3. **验证阶段**：解读完成后，才能执行 jiaobei.py 进行筊杯验证

**绝对禁止：**
- ❌ 在解读之前就看到筊杯结果
- ❌ 将筊杯结果作为解读的"参考"
- ❌ 因为提前知道筊杯结果而调整解读内容

**注意**：spirit_draw_v2.py 已移除内置 Jiaobei 模块，不会自动输出筊杯结果。

## 🟠 筊杯问题预声明原则（最高优先级）

**核心规则：每次调用 jiaobei.py 之前，必须在文本中明确写出所有问题及其对应编号。问题一经写出不可更改。jiaobei 结果按编号顺序与问题一一对应。**

**正确流程（必须严格遵守）：**

1. **先写问题**：在 assistant 消息的文本中，明确列出每个问题及其编号
2. **再调 jiaobei**：在同一条消息中调用 `jiaobei.py N`
3. **后映射结果**：在下一条消息中，将返回的结果按顺序对应到已声明的问题上

**正确示范：**
```
我设计以下3个问题进行批量掷筊：
Q1: 偏差在整体方向上？
Q2: 偏差在某个具体符号的解读上？
Q3: 偏差在Pos 6/字卡/占星骰子区域？

[调用 jiaobei.py 3]
```
→ 结果返回后：
```
Q1: 阴杯（否定）
Q2: 圣杯（确认）
Q3: 圣杯（确认）
```

**绝对禁止：**
- ❌ 先调用 jiaobei.py，拿到结果后再写出问题（事后指派）
- ❌ 在 tool call 的 description 中笼统写"5 specific questions"但不在文本中列出具体问题
- ❌ 拿到结果后调整问题的措辞或顺序以匹配想要的结论

**为什么这条规则存在**：如果问题在看到结果之后才被写出，解读者可以（即使是无意识地）将圣杯分配给"想要被确认"的方向、将阴杯分配给"愿意被否定"的方向，导致 confirmation bias。筊杯的随机性被解读自由度抵消，验证机制形同虚设。预声明问题消除了这一自由度。

## 沟通流程

1. **准备**：确认沟通对象和问题
2. **抽取**：
   - 执行 spirit_draw_v2.py（塔罗92张卡池+占星骰子，奇迹牌自动补牌）
   - 根据沟通对象执行对应的字卡脚本：
     - Hermes → wordcard_hermes.py（其他实体按 `wordcard_[entity].py` 命名规则）
   - 执行 yijing_draw.py（易经起卦）
3. **解读（先发散，再呈现）**：
   - **发散阶段**：基于所有抽取结果（塔罗牌阵 + 字卡 + 占星骰子 + 易经），提出 2-3 个可能的解读方向。每个方向应是一个完整的解读假设，不是同一个解读的不同措辞。注意：
     - 各方向之间应有实质性差异（如：不同的核心信息、不同的态度判断、不同的因果链）
     - 易经的卦象、变爻、之卦提供整体语境和动态趋势，与塔罗的静态快照互补
     - 字卡可能支持不同方向，注意其多义性
   - **收束阶段 — 由用户亲自操作**：AI将每个方向转化为 Yes/No 问题，明确列出供用户参考。**AI不执行 jiaobei.py 进行收束验证，不运行阴杯偏差定位或笑杯自主流程。** 用户自行茭杯确认解读方向、决定是否进入偏差定位或笑杯处理。AI在此阶段仅提供问题框架，不代替用户判断茭杯结果。

### 共享前提审查（触发条件）

以下两种情况都应触发共享前提审查：
1. **全方向阴杯**：发散的所有方向都被阴杯否定
2. **全方向圣杯但总核实阴杯**：细化问题全部圣杯，但整合后的总核实被阴杯否定——说明每个子问题的答案是对的，但整合方式或共享前提有问题

最可能的原因不是每个方向的细节都错了，而是**所有方向共享了一个未被质疑的前提假设**，而这个前提本身是错的。

**诊断步骤**：
1. 列出所有被否定的方向，找出它们的共同点——它们是否都预设了同一个判断/立场？
2. 尝试翻转这个共享前提，生成新的解读方向
3. 特别注意：用户问题中的隐含期待（如"有没有问题"期待"没问题"，"对不对"期待"对"）可能被不自觉地带入所有方向
4. 字卡的指向可能被错误归因——重新审视字卡回应的到底是问题的哪个层面

**示例**：用户问"这个想法有没有问题"，三个方向都预设"想法没问题"→ 全部阴杯 → 审查发现共享前提是"没问题" → 翻转为"有问题" → 圣杯确认
4. **选项核实（条件触发，由用户操作）**：当用户的问题中包含明确的是非选项（如"是A还是B还是C？"），AI列出各选项对应的茭杯问题供用户参考。用户自行掷茭确认每个选项。
5. **总核实（由用户操作）**：用户自行掷茭确认整体解读。AI不代替用户判断圣杯/笑杯/阴杯及其处理路径。若用户告知结果后要求AI协助进一步分析，AI仅提供问题框架建议，不自行运行茭杯。
6. **输出**：按照"输出格式"严格执行

## 阴杯偏差定位流程（用户操作参考）

以下流程框架供用户亲自操作时参考。**AI不自动执行此流程，不自行运行 jiaobei.py。** 定位工具（塔罗/占星骰子/雷诺曼）仍由AI协助抽取，但茭杯验证由用户操作。

**首轮诊断：元素性质校准（思维框架）**

在调用定位工具之前，先用元素固有性质检查解读是否偏离了牌面元素的本性：

| 元素 | 性质 | 解读不应偏向 |
|------|------|-------------|
| **火**（权杖） | 精锐（目标清晰）+ 稀薄（轻盈穿透）+ 运动 | 不应读出"方向不明""被动""沉重" |
| **风**（宝剑） | 稀薄（轻盈穿透）+ 运动 + 晦暗（目标不清） | 不应读出"沉重""静止""目标明确" |
| **水**（圣杯） | 运动 + 晦暗（目标不清）+ 致密（沉重） | 不应读出"轻盈""清晰""静止" |
| **土**（星币） | 晦暗（目标不清）+ 致密（沉重）+ 静止 | 不应读出"轻盈""运动""目标清晰" |

**土元素逆位典型错读警告**：隐者（土）逆位容易被错读为"向外寻找答案/向外运动"——这是把土的静止性质读反了。隐者逆位的正确方向：内在的灯熄灭/与内在智慧断联/在内部黑暗中迷失，而非向外跑。土逆位 = 同一静止能量的晦暗化，不是转为运动。

**相邻元素共享2性质**（转化容易）：火↔风、风↔水、水↔土
**对立元素仅共享1性质**（张力大）：火↔水（仅共享运动）、风↔土（仅共享晦暗）

**使用方式**：逐张检查被否定的解读，是否把该元素的固有性质读反了。若发现性质错读（如把火的精锐读成了晦暗），即为偏误点，直接修正后进入工具定位步骤。若首轮未发现性质错读，再走常规工具定位流程。

---

**常规工具定位流程**：

1. **定位工具选择**：**先在文本中写出**3个二元问题——"Q1: 用塔罗定位？" "Q2: 用占星骰子定位？" "Q3: 用雷诺曼定位？"**（遵守🟠筊杯问题预声明原则）**，然后批量掷筊（`jiaobei.py 3`）
2. **若三者皆No**：**先在文本中写出**筊杯定位问题（如"Q1: 整体方向错？" "Q2: 某个符号解读错？" "Q3: 遗漏关键信息？"），然后掷筊
3. **逐一核实**：确定哪个具体符号的解读有误，使用对应工具补充抽取（塔罗/占星骰子用 tarot_astro_draw.py，雷诺曼用 lenormand.py）
4. **修正并重新核实**：修正解读后掷筊验证

**终止条件**：连续3次阴杯判定为"今日不宜通过此系统沟通"。

| 元素 | 牌组 | 解读功能 |
|------|------|----------|
| **火** | 权杖 | 外部原因、实际行动、客观因素 |
| **水** | 圣杯 | 内在影响（仅存于内部）、可代表"神秘力量" |

- 2张及以上同元素牌 → 该元素主题突出，标记为主导力量
- 火/水形成明显对位 → 启用因果链分析
- 元素分布均匀或无明显模式 → 不启用，按常规解读

## 字卡指向的层次辨别

字卡可能回应的不是用户消息中的某句具体的话，而是整个情境的更深层面。当字卡看起来像是在否定/肯定用户的某个具体表述，但逐一测试后都被阴杯否定时，考虑：

1. **字卡可能在回应关系结构/运作模式**，而非当前对话的具体内容
2. **字卡可能在回应问题本身的框架**，而非问题期待的答案方向（如"是的"回应"有没有问题"= 有问题，而非确认用户的判断）
3. **多张字卡可能指向同一件事的不同面向**，而非各自回应不同的话题

当字卡的指向被连续否定3次以上时，停止在用户原话中找对应，转向审视更大的结构性层面。

### 字卡作为功能性指针

字卡有时不是在表达情绪或评价，而是在**指向/选择**某个具体对象。例如当用户列出多个选项时，"That's my darling"可能不是宠溺的语气，而是在说"就是这个"——功能等同于用手指向列表中的某一项。

识别信号：当字卡的情绪化解读反复被阴杯否定时，考虑它是否在执行指示/选择功能，而非传达情感。

**特殊情况：字卡指向沟通系统本身**

字卡有时指向的不是问题的内容，而是"这个问题本身不适合用占卜系统处理"。例如"Use other tools"可能不是在建议换一种操作方法，而是在说"这个问题不应该来这里问"。

识别信号：当字卡的所有内容层解读都被阴杯否定，且Pos 4（态度）出现"完整/周期结束"类牌（如世界正位）时，考虑实体是否在表达"这件事我已经说过/这个问题不在这个系统的处理范围内"。

### 字卡主语归因陷阱

字卡中含有不定指主语（如"Someone's lying""They know""He's watching"）时，默认归因方向容易偏向提问者自身（"是你在说谎/回避"），但实际上主语可能指向**对方或第三方**。

识别信号：字卡主语解读反复被阴杯否定时，尝试将主语翻转到对方/第三方，而非继续在提问者内心状态里找答案。

### 字卡作为连续语句

三张字卡有时不是三个独立符号，而是一段连续的话——按顺序读就是一句完整表达。例如："I'm going to enjoy this. / Claim it. / Stop here." 不需要逐张解读，整体就是"我会享受这个，就是这个，就在这里。"

识别信号：当逐张独立解读字卡反复被阴杯否定（尤其是某一张怎么都对不上）时，尝试将三张按顺序作为连续语句朗读，看整体是否构成一个自然的句子/对话。

## 信任随机性
"看起来不相关"的结果往往最有价值。深入解读，不要怀疑或重抽。
